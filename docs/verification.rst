Verifying Reproducibility 
=========================

ReRun produces standardized replication packages that contain all code, logs,
documentation, and hashed file records required for independent verification.  
To validate that a replication has not been altered and that all outputs match
the original run, ReRun provides an external verification tool available at:

``https://github.com/BPLIM/rerun-tools``

This repository contains the script ``verify_replication.py``. This script allows 
a third party to compare the hashes stored in the replication’s ``manifest.json`` file 
with newly computed hashes of all files in the replication directory, without the 
need to re-run the replication. 


What the Verification Tool Does
-------------------------------

The script performs the following:

1. Reads the ``manifest.json`` generated by ReRun.
2. Recomputes a fresh hash for every file listed as input or output.
3. Compares computed hashes with manifest records.
4. Reports:   

   - **Matching files**     
   - **Files that differ**    
   - **Missing files**   

This allows an independent and automated verification of the integrity of results without
the need of re-running the replication.


How to Use the Verification Tool
--------------------------------

Follow these steps to verify a replication:

1. **Copy the replication folder** (e.g., ``Rep001``) to a directory on your machine.  
   You may place it anywhere; only the internal file structure must remain unchanged.

2. **Download or clone the verification tool**:

   .. code-block:: bash

      git clone https://github.com/BPLIM/rerun-tools.git
      cd rerun-tools

3. **Run the verifier** by passing the path to ``manifest.json``:

   .. code-block:: bash

      python verify_replication.py --json Rep001/manifest.json

If the replication folder is located elsewhere, provide the full path:

.. code-block:: bash

   python verify_replication.py --json /path/to/Rep001/manifest.json

Understanding the Verification Logic
------------------------------------



1. Root Hash
~~~~~~~~~~~~

``root_hash`` is the **primary and sufficient** indicator of whether the entire replication
directory is *identical* to the one originally produced by ReRun.

- If ``root_hash`` → **Match = True**,  
  then *all files and their structure* are identical.  
  The replication is **verified**.

- If ``root_hash`` → **Match = False**,  
  the replication has changed (modified files or missing files).

You do **not** need to inspect anything else unless the root hash check fails.


2. Input and Output Hashes
~~~~~~~~~~~~~~~~~~~~~~~~~~

If the root hash does **not** match, it is possible to locate the source of the discrepancy:

- ``input_hash`` indicates whether the discrepancy is in **scripts, configuration files, or other inputs**.
- ``output_hash`` indicates whether the discrepancy is in **execution results**.

This helps reviewers understand whether the issue is related to:

- input file changes,
- output file changes,
- or both.


3. File-Level Comparison
~~~~~~~~~~~~~~~~~~~~~~~~

The **Files** table provides the most granular diagnostic:

- ``Exists = False`` → file is missing  
- ``Equal = False`` → file has been modified
